## 1. 定位

**待定，刻意不写死。** 先把 MVP 框架做出来给第一批用户，用真实行为反馈来明晰定位（Rae 决定，2026-07-12）。产品结构以下述模块为准。

## 2. 角色与记忆边界

三个角色，**agent 身份 = 记忆边界**：

| 角色 | 是什么 | MVP 可见范围 |
|---|---|---|
| A 的私人 agent（军师） | A 的军师/朋友（**不是 A 的分身**，永远以自己的身份说话） | A 的 DM + A 的 about me 信息 + A 开了「AI 模式」的日记本 |
| B 的私人 agent（军师） | 同上，对称 | B 侧同上 |
| Bird | 情侣共同拥有的 AI，具体用途先不限制、观察用户行为 | 群聊全部上下文 + 调解卡片提交（仅调解流程内，明示） |

规则（出发点式）：

- **agent 的可见范围 ≤ 它主人的可见范围**——agent 知道的都是主人本来就看得到的东西，因此它在任何场合说话都不可能泄露对方的隐私；后续给任一 agent 增加数据源（群聊、日记等）时以此为唯一判据，不再逐次讨论。
- **Bird 没有 DM**——私人陪伴由军师承担，第二个私聊入口徒增困惑；Bird 只活在共同场合。
- **军师价值观**：忠于主人。详细行为要求 Rae 后续单独给；system prompt 保持轻约束，**不用架构性限制去框模型能力**。

## 3. 模块与 MVP 范围

### Onboarding（MVP）

新用户开屏 onboarding：quick question 获取基本信息（少数必填、多数可 skip、之后可补），答案放在 about me；**邀请码也放在 about me**。

### 模块 1：agent 陪伴/军师（MVP）

- 每人一个私人 agent，DM 形态（复用现有 persona 链路，换军师 prompt）。
- 陪伴/军师。
- 主动提醒重要事项（纪念日/生日/月度推送等）。支撑机制：**主动日期记忆**（Rae 已确认）——军师在对话中听到重要日期问一句"要我记住吗？"，写入结构化重要日期表；提醒读这张表。
- 派遣（代主人去群里和对方聊，以军师/朋友身份而非分身）：**后面做**。做时遵守"私人 agent 不与对方单独相处（只在双方都在场的群里发言）"。

### 模块 2：群聊（MVP）

- 共同拥有的一个 Bird，具体用来做什么先不限制，观察。一对情侣一个群。
- **@bird 才出来**（含引用），不 @ 保持安静；Bird 知道所有群聊上下文。
- 不再有 DM bird 功能。
- 空白群聊冷启动：输入框上方**四个轻入口**——帮我们看看 / 一起做个决定 / 有件事想说清楚 / 矛盾调解。
- 两种模式，Bird 开场问"你们想在这里一起聊，还是先分别跟我说完，我再帮你们整理？"：
  - **直接说（MVP）**：就地在群里，Bird 中立立场，帮双方把话说出来、分析问题、提供建议。
  - **分开说（MVP，调解卡片）**：表单式私密提交——群里出现调解卡片 → 各自点进去回答 Bird 的引导问题（仅本人可见）→ 双方都提交后 Bird 生成共享议程发进群。避免即时防御和互相打断。私密提交是 Bird 唯一触碰个人侧内容的通道，属明示交给调解员。

### 模块 3：日记本（MVP，纯文本）

- 「我的日记」（私有）+「我们的故事」（共享，起个更 romantic 的名字）。
- **新建日记**：弱文字提示（未来规划/旅行规划/…）。
- **AI 模式开关**：按 用户×日记本 各自控制（"允许我的 agent 读这本"，默认关）。开启后该用户的军师可读该本；共享本同理——开关只影响自己的军师，且只暴露自己本就可见的内容（符合 agent≤主人 规则），故无需对方同意。Bird 不读日记。
- 后面做：多模态；私人 agent 往日记里记东西（含人写/agent 写分区、"agent 写共享区须经主人确认"闸——还没想清楚写哪本怎么写）；AI 引导/comment（可选项）；轻量标记 Moment/promise/plan/unfinished。

### 模块 4：about me（MVP 仅做个人信息页壳）

- MVP：个人信息页 = onboarding 答案 + 重要日期 + 邀请码入口。
- 后面做：恋爱人格测试（爱的语言/冲突类型/依恋类型）、重要事项完整版（农历&阳历/相识相恋 xx 天）、Insight from bird（月度总结信件 + Relationship Changelog + 第一封信；与记忆系统一起，边服务第一批用户边 build）。

## 4. 单人期与邀请

- **单人期 = 只有军师 DM**（+ 我的日记、about me），**群聊等 B 接受邀请后创建**（wiki 已确认；Bird @才响应、四入口皆双人场景，单人群无意义）。
- 旧「交互/能力」节（备忘录权限、语音、时光胶囊等）已在 wiki 中划除，不属本 spec。
- 邀请：沿用 07-03 spec 钥匙机制（`chirp_invites`、redeem 幂等、错误文案）；B redeem 后走同一开屏 onboarding，获得自己的军师，进入群聊；历史群消息对 B 可见。

## 5. 数据层增量（相对 07-03 spec）

- 沿用：`chirp_invites`、RLS owner→membership 改造、Realtime 订阅、消息双列约定、visibleRunLock。
- 移除：bird_dm 会话不再创建（旧表/链路保留，入口下线）；memoryScope 跨房间裁剪规则简化为"按 agent 身份取各自会话范围"。
- 新增：
  - 重要日期表（user_id、label、date、lunar 标记、scope=personal/couple）。
  - 日记表（book：类型 my/ours/custom + 标题；entry：作者、时间；author_type 字段预留 agent）+ AI 模式开关表（user_id × book_id，默认关）。
  - 调解卡片表：状态机 pending_submissions → agenda_posted；私密提交内容仅 service role 可读。
- ⚠️ 记忆架构既有定论（"Bird 拥有全量全局记忆"）在本设计中反转：Bird 只持有群聊+调解层。实施前重过 memory 决策链与 distiller 现状。

## 7. 非目标（MVP 明确不做）

派遣、agent 写日记、persona 社区、agent 进微信、恋爱人格测试、月度信件/第一封信/Changelog、多模态、语音输入、AI 日记引导/comment、每日一问、旧多 persona 星球功能恢复（继续隐藏不删）、Love letter 时光胶囊、结婚 sell。

## 8. 遗留与风险

- RLS 回归、`chirp_planet_members` 线上结构核对：沿用 07-03 spec §10。
- Bird 调解冷启动：Bird 仅见过群聊（大概率稀疏），首次调解无积累；分开说的提交本身即信息收集，直接说依赖开场引导。
- 军师主动性（提醒频率/建议时机）需真实调参，属可调项。
- 军师价值观细则待 Rae 提供后补入 prompt。
